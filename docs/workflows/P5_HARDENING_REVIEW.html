How should `/standard-workflow` be revised to prevent P5 Merge Queue and pre-commit bypasses?

Long image

A

Answer

Move the three violated P4–P5 rules from prose-only instructions into deterministic scripts and PreToolUse hooks (worktree_land.sh preflight, land --wait, guard-git-commands.sh, and analyze-destructive.mjs).

  1. Blocking raw git worktree remove and gh pr merge teardown chains in PreToolUse hooks prevents premature worktree deletion while a PR is still OPEN in the Merge Queue.1
  2. Adding --wait to worktree_land.sh land polls GitHub until state == "MERGED" before fast-forwarding $MAIN_ROOT and pruning local and remote branches (GH006-safe).2
  3. Adding worktree_land.sh preflight and aligning ship-and-land Stage 1 with CLAUDE.md#ship guarantees ksm_quality_gates.sh and agent_artifact_policy.mjs run before every commit.3

How does the hardened P4–P5 pipeline execute end to end?

Diagram structure
  • Run preflight gates preflight
  • Raw teardown chained? hook_guard
  • Enqueue and poll MERGED mq_wait
  • Pull main and prune worktree teardown
  • deploy-check then STG to PROD deploy_gate
  • hook_guard → mq_wait · via worktree_land.sh
  • mq_wait → teardown · state is MERGED
  • preflight → hook_guard · commit and PR
  • teardown → deploy_gate · HEAD is master
  1. Run preflight gates ↗

    Execute worktree_land.sh preflight (or workflow_conductor.mjs verify) inside .worktrees/<slug> to run verify_session_delta.sh, ksm_quality_gates.sh check --scope changed --base origin/master, agent_artifact_policy.mjs, and harness_surface_gate.mjs before committing.

  2. Raw teardown chained? ↗

    PreToolUse hooks (guard-git-commands.sh and analyze-destructive.mjs) hard-deny raw git worktree remove and any gh pr merge chained with git worktree remove, git branch -D, or git push --delete.

  3. Enqueue and poll MERGED ↗

    worktree_land.sh land --pr <N> --auto-merge --wait enqueues the PR in GitHub Merge Queue and polls every 15s until state == "MERGED" and mergedAt != null (aborting if checks fail or the PR is dequeued).

  4. Pull main and prune worktree ↗

    Only after GitHub confirms MERGED, worktree_land.sh switches to $MAIN_ROOT, runs git pull --ff-only origin/<default-branch>, removes .worktrees/<slug>, and deletes the local and remote branch without triggering GH006.

  5. deploy-check then STG to PROD ↗

    Run worktree_land.sh deploy-check from $MAIN_ROOT to confirm CWD == $MAIN_ROOT, clean working tree, and HEAD == origin/<default-branch>, then deploy STG followed by PROD.
