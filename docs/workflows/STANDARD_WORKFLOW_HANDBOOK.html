How does the Wahyz Standard Development Workflow run from prompt or L3 signal to landed PR?

Long image

A

Answer

A two-layer Conductor + State Machine + Hook Back-Edge architecture (standard-workflow in INV + workflow_conductor.mjs and worktree_land.sh in DOM) executes the 4 Delivery Pillars across 6 deterministic phases and 7 Git/PR stages.

  1. The user-scope standard-workflow skill (WahyzDAD/wahyz_agent_profile#20) sequences existing third-party and first-party skills without modifying upstream vendor files.1
  2. tools/ci/workflow_conductor.mjs (WahyzMaster/wahyz_omni#1844) seeds LOOP_CONTRACT.md and .workflow-state.json, locks Protected Verification Files with SHA-256 hashes, and enforces stopAt safety boundaries.2
  3. Every feature or repair binds 4 mandatory pillars: Linear Filing (GLO-XXX), Usage Guides (Docs-as-Code), In-App Tutorials (TutorialFlowContract), and Changed-Scope CI Gates (PR #1841).3
  4. ship-and-land (WahyzDAD/wahyz_agent_profile#17 + scripts/worktree_land.sh in #1841) lands PRs without the --delete-branch worktree trap and prunes only MERGED_CLEAN worktrees.4

How does the end-to-end 6-phase pipeline connect L3 signals, the 4 pillars, and 7-stage landing?

Diagram structure
  • P0. Prompt or L3 Signal p0
  • P1. Worktree & SHA-256 Lock p1
  • P3. 4-Pillar Implementation p3
  • P2. Plan & Arch Fit p2
  • P4. Stop Hook & CI Gates p4
  • P5. 7-Stage Ship & Land p5
  • p0 → p1 · workflow:init
  • p1 → p2 · LOOP_CONTRACT
  • p2 → p3 · PLANNED
  • p3 → p4 · BUILT
  • p4 → p3 · hash or tag fail
  • p4 → p5 · VERIFIED
  1. P0. Prompt or L3 Signal ↗

    Trigger via natural-language prompt (mcp-routing-hint.sh) or L3 operational signal (crashlytics, health_check, tutorial_abandonment, customer_issue).

  2. P1. Worktree & SHA-256 Lock ↗

    Create .worktrees/<slug> from origin/master and run npm run workflow:init to write LOOP_CONTRACT.md + .workflow-state.json with SHA-256 locks on Protected Verification Files.

  3. P2. Plan & Arch Fit ↗

    Run codegraph_impact, check Harness^2 prior experiences in LOOP_CONTRACT.md, and run workflow_conductor.mjs advance --to PLANNED.

  4. P3. 4-Pillar Implementation ↗

    Build (1) Clean Architecture code, (2) Usage Guide (src/<id>.md), (3) In-App Tutorial (TutorialFlowContract), and (4) @Tags tests.

  5. P4. Stop Hook & CI Gates ↗

    verify_session_delta.sh and npm run workflow:verify enforce @Tags([...]), SHA-256 protected file integrity, quality_gates.mjs --scope changed, and harness_surface_gate.mjs.

  6. P5. 7-Stage Ship & Land ↗

    Run npm run workflow:ship and worktree_land.sh (checks, land, gc --apply) while enforcing stopAt=pr-opened on autonomous signal runs.
